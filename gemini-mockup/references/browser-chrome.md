# Browser-chrome prompt fragment

Universal Layer 1 framing for every mockup generated by `gemini-mockup`.

Concatenate this into the prompt before the project-specific visual
identity. Replace `{URL}` with a plausible URL for the active project + the
specific route the screen is at.

---

A high-fidelity UI mockup screenshot rendered inside a realistic macOS Safari
browser window. The browser chrome MUST include:

- Three traffic-light buttons (red, yellow, green circles) in the top-left
  corner of the title bar.
- A unified address bar showing the URL `{URL}`.
- A tab bar with one active tab whose title relates to the page being shown
  (e.g., "Login — Reduit", "Account Dashboard — joe-links").
- The browser window has a subtle drop shadow and sits on a neutral desktop
  background — a soft graphite (#1a1a1a) for dark-mode mockups, a soft
  off-white (#f5f5f5) for light-mode mockups.

The browser frame should look like a recent (2024+) macOS Safari build — not
Chrome, not Firefox, not a generic browser-shaped rectangle. Get the
proportions right: tab bar above the address bar, address bar above the
content. No bookmarks bar unless the description explicitly asks for one.
No browser extensions visible.

The viewport inside the browser shows the actual UI being mocked up. The
viewport is roughly 1280 wide × 800 tall in mockup-pixel terms (the overall
image is 1536×1024, the chrome takes the top ~80px and a thin border around
the rest).
